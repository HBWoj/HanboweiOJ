# 题目与测试数据规范

- 文档版本：0.1
- 目标：让题目可审核、可复现、可安全判题，并能服务课程学习

## 1. 题目元数据
建议每题至少包含：
- id：稳定题目 ID。
- slug、title：站内标识与标题。
- statement：原创题面 Markdown。
- input_format / output_format。
- constraints：明确上下界、数据类型和特殊条件。
- samples：公开样例及解释。
- time_limit_ms / memory_limit_mb。
- language_policy：允许语言与编译标准。
- knowledge_point_ids：关联知识点。
- level、difficulty、tags。
- source：原创、经授权改编或公开来源信息。
- version、status、reviewer。

## 2. 题目内容结构
1. 题目背景（可选，简洁并服务于问题）。
2. 任务描述。
3. 输入格式。
4. 输出格式。
5. 数据范围。
6. 样例输入。
7. 样例输出。
8. 样例说明（可选）。
9. 限制与子任务（如需要）。

题面必须自洽、无歧义。学生所需的所有定义、假设、范围和精度应在题面中出现。

## 3. 测试数据包
隐藏测试数据只存在于受限的题目数据存储和 Judge Worker 可读环境。数据库中保存受控引用和校验摘要，不通过普通题目 API 返回隐藏内容。

每个测试包应包含：
- manifest（文件名、大小、hash、对应版本）。
- 输入文件与标准输出。
- 数据生成器及随机种子（如适用）。
- 参考程序或独立校验器。
- 覆盖边界情况的说明。
- 数据包版本和审核记录。

至少覆盖：
- 最小输入、最大输入。
- 边界下标、空/单元素情况（适用时）。
- 全相等、递增、递减、重复值等结构性情况。
- 数值极值、溢出风险和复杂度压力。
- 特殊格式、空白字符和多组数据（适用时）。

## 4. 评测结果
面向学生的状态：
- Waiting / Queued
- Compiling
- Running / Judging
- Accepted
- Wrong Answer
- Time Limit Exceeded
- Memory Limit Exceeded
- Runtime Error
- Compilation Error
- System Error

学生只能查看公开样例和允许公开的诊断。禁止将隐藏用例、期望输出、完整测试文件路径或标准答案直接返回前端。

## 5. 题目质量审查
发布前由题目作者以外的审核者检查：
- 题意是否有唯一、明确的解释。
- 数据范围是否足以支撑算法选择。
- 标准解法和复杂度是否正确。
- 暴力程序或随机对拍是否发现反例。
- 测试点是否覆盖边界和潜在错误实现。
- 题面、样例、标准程序和数据包版本是否一致。
- 题目是否有明确版权来源和授权状态。
- 题目难度与知识点先修是否合理。

## 6. 版权原则
优先原创题目。对外部题目只在获得授权或适用许可后导入，并保留来源、许可和修改记录。不得批量复制其他 OJ 的题面、测试数据、题解或隐藏用例。
