# 安全、隐私与未成年人保护

- 文档版本：0.1
- 状态：首版安全基线；上线前必须由实际部署环境复核

## 1. 学生代码是不可信输入
判题 Worker 必须：
- 使用非 root 用户运行。
- 禁用特权容器、宿主 Docker socket、宿主目录写挂载。
- 默认禁用网络访问。
- 使用临时、隔离的工作目录。
- 限制 CPU 时间、墙钟时间、内存、进程数、文件大小、磁盘和 stdout/stderr 输出量。
- 设置合理的系统调用限制，并在可用时使用 namespaces、cgroups、seccomp 和只读根文件系统。
- 对编译和运行分别计时、记录退出码。
- 任务结束时杀死整个进程组并销毁环境。
- 定期更新基础镜像、编译器与运行时；记录镜像摘要。
- 不允许学生选择任意镜像、任意启动命令或任意挂载路径。

单纯使用 Docker 容器不等同于完整安全边界。公网生产环境需评估更强隔离技术、专用节点和纵深防御。

## 2. 业务安全
- API 对每个请求检查身份、角色、班级关系与资源所有权。
- 密码使用成熟哈希算法；会话使用安全 Cookie 或受控令牌。
- 对登录、提交、AI 请求和管理操作实施速率限制。
- 上传内容校验类型、大小与文件名；文件存储与应用执行隔离。
- 管理员操作和内容发布保留审计日志。
- 秘钥只放在 Secret 管理或环境变量，不提交到 Git。
- 生产数据库与评测数据定期备份，并验证恢复流程。

## 3. 未成年人数据最小化
- 只收集提供教学功能必需的数据。
- 不在公开页面展示真实姓名、学校、联系方式或精确位置。
- 学生档案默认私有；教师和家长访问必须有明确授权与范围。
- 设定数据保留、导出、更正和删除流程。
- 对 AI 服务只发送完成任务所需的最少信息；评估第三方服务的数据处理和保留政策。
- 不将学生代码、学习表现或画像用于广告定向。
- 上线前依据运营地区的适用法律完成隐私告知、监护人授权与数据治理评估。

## 4. AI 学习分析的边界
AI 只能在证据范围内给出建议：
- 观察事实：例如编译器报告的行列、评测状态、公开诊断和重复提交模式。
- 推测：例如「可能对数组边界理解不牢」，必须明确写为可能原因。
- 未知：证据不足时说明无法判断，并邀请学生检查思路或向教师求助。

不要仅凭单次 WA 推断「粗心」「基础差」。不要生成对智力、人格、心理状况或未来成绩的诊断。

## 5. 正向教学与防止依赖
- 默认先给提示和知识回顾，再按需逐层展开。
- 不默认直接生成整题可提交代码。
- 对代码修改建议解释原理，并鼓励学生自己完成关键步骤。
- 将系统错误、题目错误和评测基础设施故障与学生错误分开。
- 不以羞辱、恐吓、排名羞辱或连续打卡压力推动学习。

## 6. 发布前检查
任何公网部署前，必须完成威胁建模、沙箱逃逸测试、资源耗尽测试、越权测试、密钥扫描、备份恢复测试和数据隐私审查。
