# 开发路线图

当前总策略：先让小范围端到端流程真实运行，再扩展内容和功能。每个阶段以可验证的交付物结束。

## Phase 0：项目基础（当前）
- [x] 检查初始仓库与默认分支。
- [x] 建立独立功能分支。
- [x] 编写产品愿景、需求边界与安全原则。
- [x] 设计课程、题目和判题领域模型。
- [ ] 评审首版架构决策。
- [ ] 约定代码风格、分支策略、PR 和 CI。

## Phase 1：最小可运行骨架
- 建立 monorepo 目录、Web、API、数据库迁移和本地开发配置。
- 实现健康检查、基础错误处理、配置管理和结构化日志。
- 建立 CI：格式检查、静态检查、单元测试、依赖安全扫描。
- 提供一套示例课程与原创练习数据。
- 验收：干净环境可按文档启动；基础测试通过。

## Phase 2：课程与题库
- 用户角色与权限。
- 大纲版本、知识点、先修关系和课程详情。
- 题目元数据、题面展示、教师内容管理。
- 题目版本、审核和发布流程。
- 验收：教师可创建草稿、审核和发布；学生可按路径学习。

## Phase 3：判题 MVP
- 提交 API、队列、调度器和隔离 Worker。
- 首版 C++ 编译与判题状态。
- 单测、集成测试、边界测试和安全测试。
- 提交历史和资源用量展示。
- 验收：公开测试环境通过端到端题目；沙箱约束经验证。

## Phase 4：学习闭环
- 错题归档与原因分类。
- 规则优先的错误证据提取。
- 薄弱知识点统计与复习任务。
- 学习进度和阶段报告。
- 验收：错题建议能追溯证据，学生可修正误判。

## Phase 5：AI 教学支持
- 分层提示、代码讲解和针对性练习。
- AI 结果引用提交证据与课程内容。
- 教师复核与用户反馈机制。
- 成本、延迟、隐私和效果评估。
- 验收：不暴露隐藏测试和标准答案，且能区分事实与推测。

## Phase 6：部署与稳定性
- 正式环境配置、域名和 HTTPS。
- 监控、告警、备份与灾难恢复演练。
- 压力测试、权限审计和沙箱安全评估。
- 学校/班级试点后逐步扩大。

## 当前不做
不提前开放公开排行榜、论坛、复杂竞赛系统或多语言评测，直到核心学习与判题闭环稳定。
